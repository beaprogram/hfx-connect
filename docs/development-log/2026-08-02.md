### Design

Full rationale in
[ADR-013](../decisions/ADR-013-interactive-map-and-geolocation-design.md).
The one genuinely hard design question was **where session state lives**
(search centre, radius, geolocation status, selection) given three
competing constraints: coordinates must never be in the URL/storage; the
state must survive a filter-driven `/resources?...` navigation and a
resource-detail-page round trip; and no new state-management dependency
was warranted. Resolved by mounting a `MapSearchProvider` React Context
at a new `app/resources/layout.tsx` — a layout, not a page, so it
persists across exactly the navigations that needed to preserve it.

### A Bundler-Specific Gotcha, Diagnosed and Fixed

Leaflet's default marker icon computes its image URLs relative to the
Leaflet CSS file's own location, which breaks under any JS bundler — a
known, structural issue, not specific to this Next.js version, but this
project's specific static-image-import loader returns a `StaticImageData`
object rather than a raw string, so the standard
`delete L.Icon.Default.prototype._getIconUrl` /
`L.Icon.Default.mergeOptions(...)` fix needed a small `resolveAssetUrl`
helper to normalize either shape. Confirmed working via a real production
build and, later, via real marker icons rendering in a live browser
screenshot.

### A Real Bug Found During Manual Verification, Not by the Automated Suite

The `view`/`radiusKm` URL-mirroring effect (meant only to make the
current presentation shareable) initially re-fired on every pathname
change and unconditionally rewrote the current URL — which meant clicking
"View details" from Map mode and landing on
`/resources/[slug]` immediately picked up a stray `?view=map&radiusKm=5`
query string that means nothing on a detail page. The automated test
suite didn't catch this because it mocked `usePathname()` to a fixed
value; a real headless-Chromium session (Playwright, already cached in
this environment) driving an actual `router.push` navigation did. Fixed
by scoping the mirroring effect to `pathname === "/resources"` exactly,
then added a dedicated regression test that exercises a real mocked
pathname change to prevent a silent regression.
