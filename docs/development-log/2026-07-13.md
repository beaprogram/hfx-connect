## Technical Decisions

- Used plain JDBC (`spring-boot-starter-jdbc`) rather than Spring Data JPA for this
  milestone: nothing yet needs an ORM (no entities exist), and JDBC is sufficient for
  connectivity and Actuator's database health check. JPA will be introduced in
  Milestone 3 once there are real entities to justify it.
- Kept `docker-compose.yml`'s default port at the standard `5432` (correct for the
  general/typical case) rather than changing the project default because of this one
  machine's local conflict; the conflict and its fix are documented instead, since
  baking a nonstandard default into the repository to work around one developer's
  machine would be the wrong fix for everyone else.
- Did not touch the pre-existing native PostgreSQL service that caused the port
  conflict — it is unrelated infrastructure this project does not own.

## Problems Encountered

1. No Docker runtime installed on this machine.
2. `postgis/postgis` publishes no `linux/arm64` image.
3. Spring Boot 4.1 does not auto-configure Flyway (removed, not merely renamed).
4. `TestRestTemplate` and its `RestTemplateBuilder` dependency were relocated to new
   Spring Boot 4 modules not included by default.
5. Testcontainers 2.x relocated and changed the generic-type signature of
   `PostgreSQLContainer`.
6. Testcontainers' Ryuk sidecar container failed to start under Colima due to a
   host/guest Docker socket path mismatch.
7. A pre-existing native PostgreSQL service on this machine was already bound to port
   5432, causing the backend to silently connect to the wrong database.

## Resolution

Each problem above was diagnosed from the actual error/classpath evidence (not
assumed) and resolved directly: installed Colima; pinned `platform: linux/amd64` and
smoke-tested it; added an explicit Flyway configuration class and documented it as
ADR-004; added the two additional Spring Boot 4 modules and the
`@AutoConfigureTestRestTemplate` annotation; updated the Testcontainers import and
removed the now-unsupported generic type parameter; set
`TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE`; validated the stack on an overridden port and
documented the port-conflict scenario for future readers, without touching the
unrelated native service.
