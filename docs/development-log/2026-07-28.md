### Design

Wrote [ADR-010](../decisions/ADR-010-keyword-search-design.md) before
implementing: a single unified `ResourceRepository.search`/
`ResourceService.search` query replacing the previous two-method
(`listActive`/`listActiveByCategory`) pair, since adding keyword search as
a second independent optional filter would otherwise have multiplied into
four method combinations; searchable fields limited to
`name`/`description`/`addressLine1`/`city` (province, postal code, category
name, and contact fields deliberately excluded, each with a stated reason);
`%`/`_` wildcard escaping via a fixed `ESCAPE '\'` clause and an
already-escaped bound parameter; and a deliberate decision **not** to add a
`pg_trgm`/GIN index yet, given this project's actual MVP dataset size —
documented as a revisitable assumption, not an oversight.

### Two Self-Authored Test Bugs, Found and Fixed Before Considering the Milestone Done

Two of this milestone's own new tests initially failed — not because of an
implementation defect, but because the test's own search phrase wasn't
actually a contiguous substring of the seeded resource name (e.g.
`"Workshop A " + marker` does not contain `"Workshop " + marker` as a
substring — the inserted `"A "` breaks it). Both were root-caused by
re-reading the actual assertion against the actual seeded data (not assumed
to be an implementation bug) and fixed by either using a keyword genuinely
shared by both seeded resources (letting the category filter be what
narrows the result) or removing the interposing word from the seeded name.
A concrete reminder that a new test failing needs its own logic verified
just as carefully as the code it's testing, especially for substring-match
assertions.
