## Technical Decisions

- Repository visibility: public, on the `beaprogram` GitHub account — confirmed
  explicitly before creating the repository, since visibility is an externally visible
  decision the automation would not make unilaterally.
- Documentation split into a `docs/product/` subdirectory not explicitly named in the
  original repository-layout sketch, because the product-definition deliverables
  (problem statement, personas, scope, journeys, stories) are substantial enough to
  need their own files rather than being crammed into the single milestone document.
- ADRs were limited to three decisions already genuinely implied by the given
  technology stack (monorepo, PostgreSQL + PostGIS, REST). Token-based authentication
  design was deliberately not written as an ADR yet — it belongs to Milestone 5, once
  the actual token/cookie design is implemented rather than speculated about.
