## Technical Decisions

- `categories.id` is `BIGINT IDENTITY`, not UUID — see ADR-005; this establishes the
  project's default reasoning (stable/admin-managed entities get numeric IDs, larger
  publicly-created content entities get UUIDs) for future domains to follow or
  explicitly override.
- Slugs are always derived from the name; the API does not accept a caller-supplied
  slug. Chosen to keep the validation surface small for a feature with no
  demonstrated need for custom slugs yet — revisit if a real product need for custom
  slugs emerges.
- Pagination is validated with plain `@RequestParam` bindings and manual bounds
  checking, not Spring's automatic `Pageable` resolution — gives precise control over
  producing the project's own `400 INVALID_PAGINATION` shape for out-of-range input
  instead of relying on the default resolver's behavior.
- `POST /api/v1/categories` is intentionally left unauthenticated this milestone;
  documented in five separate places (API docs, milestone doc, root README, backend
  README, controller Javadoc) rather than mentioned once, since it's a real,
  currently-exploitable gap that anyone reading any one of those documents should see.

## Problems Encountered

1. Hibernate schema validation failed at first JPA-enabled startup:
   `missing table [categories]`, despite the migration existing.
2. `FlywayMigrationIntegrationTest`'s idempotency assertion (Milestone 2B) became
   stale once a second migration existed.

## Resolution

1. Diagnosed as a bean-instantiation-order problem (Flyway bean vs. JPA's
   `entityManagerFactory` bean, with no auto-configuration gluing them together in
   Spring Boot 4.1 the way it used to). Fixed with
   `EntityManagerFactoryDependsOnPostProcessor`, documented in
   `FlywayMigrationConfig`'s Javadoc and in this milestone's Risks section.
2. Rewrote the assertion to compare the history row count against the distinct-version
   count, which verifies the same invariant (no migration ever applied twice) without
   hardcoding a number tied to how many migrations currently exist.
